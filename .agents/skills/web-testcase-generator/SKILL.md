# Web Test Case Generator Skill

Skill นี้ใช้สำหรับเข้าไปสำรวจระบบ/หน้าเว็บจริง แล้วสกัดข้อมูลฟิลด์ เงื่อนไข Validation และ Flow การทำงาน เพื่อเขียน **Test Case ภาษาไทย** ในรูปแบบมาตรฐานสำหรับ QA / Tester

> ⚠️ **สำคัญ:** ทำเฉพาะ scope / ฟังก์ชันที่ผู้ใช้สั่งเท่านั้น ห้ามทำ scope อื่นนอกเหนือจากที่ระบุ

---

## ฟังก์ชันหลักของระบบ STS (Function List)

ใช้ตารางนี้เพื่อ **map รหัสฟังก์ชัน → เลข XX** ในรหัส TS/TC:

| รหัสฟังก์ชัน | XX | ชื่อฟังก์ชัน (ภาษาไทย) |
|---|---|---|
| FN-STS-01 | 01 | เข้าสู่ระบบ |
| FN-STS-02 | 02 | รายงานสถานะนักเรียน |
| FN-STS-03 | 03 | แสดงรายชื่อนักเรียน |
| FN-STS-04 | 04 | แสดงรายชื่อครู |
| FN-STS-05 | 05 | แสดงห้องเรียนทั้งหมด |
| FN-STS-06 | 06 | จัดการภาคเรียนและห้องเรียน |
| FN-STS-07 | 07 | จัดการหลักสูตร |
| FN-STS-08 | 08 | นำเข้าข้อมูล |
| FN-STS-09 | 09 | จัดการข้อมูลพื้นฐาน |
| FN-STS-10 | 10 | เช็กชื่อ |
| FN-STS-11 | 11 | จัดการลิงก์ห้องเรียน |
| FN-STS-12 | 12 | จัดการนักเรียน |
| FN-STS-13 | 13 | จัดการข้อมูลครู |
| FN-STS-14 | 14 | จัดการผู้ใช้งาน |
| FN-STS-15 | 15 | จัดการกลุ่มเมนู |
| FN-STS-16 | 16 | ตั้งค่าระบบ |

> 📌 ตัวอย่าง: หน้า "จัดการข้อมูลพื้นฐาน" = FN-STS-09 → TS-STS-**09**-01, TC-STS-**09**-01-01

## 1. การเตรียมข้อมูลและ Login เข้าสู่ระบบ

1. อ่านค่าจากไฟล์ `.env` ที่ root ของโปรเจกต์:
   - `BASE_URL`: URL ของระบบ (เติม `https://` หากยังไม่มี)
   - `USERNAME`: ชื่อผู้ใช้งาน / บัญชีเข้าสู่ระบบ
   - `PASSWORD`: รหัสผ่าน
2. เปิด Browser เข้าไปยัง `BASE_URL` และทำการ Login ด้วย Username/Password ที่ระบุ
3. นำทางไปยังเมนูหรือหน้าจอที่ต้องการทดสอบ

## 2. การสำรวจหน้าจอและเงื่อนไข (Exploration)

เมื่อเข้าสู่หน้าจอเป้าหมายแล้ว ให้ตรวจสอบองค์ประกอบต่อไปนี้:
- **เมนูและปุ่ม:** เช่น เมนู "ข้อมูลพื้นฐาน", ปุ่ม "เพิ่มรายการ", ปุ่ม "แก้ไข", ปุ่ม "ลบ", ปุ่ม "บันทึก"
- **ฟิลด์ข้อมูลใน Form:** เช่น รหัส, ชื่อภาษาไทย, ชื่อภาษาอังกฤษ, ลำดับแสดงผล, สถานะ
- **เงื่อนไข Validation / Error Message:**
  - เงื่อนไข Required (ไม่ได้กรอกข้อมูล)
  - รูปแบบตัวอักษร (เช่น ภาษาไทย, ภาษาอังกฤษ, ตัวเลข, สัญลักษณ์พิเศษ, ขีดล่าง `_`)
  - ความยาวตัวอักษร (Min / Max length)
  - ข้อความแจ้งเตือนข้อผิดพลาด (Error / Warning message) ที่แสดงบนหน้าจอจริง

## 3. รูปแบบ Test Case มาตรฐาน (Template)

ทุก Test Case ที่สร้างขึ้น **ต้องใช้โครงสร้างและลำดับตามฟอร์มนี้เท่านั้น**:

```text
### TC-<รหัส>: <หัวข้อ Test Case>

- **TC ID:** TC-<รหัส>
- **TC Description:** <คำอธิบายการทดสอบ เช่น ตรวจสอบการกรอกข้อมูลเพิ่มรายการ "..." ด้วยรหัสที่ผิดพลาด>
- **Test Step:**
  1. เข้าสู่หน้า "<ชื่อเมนู/หน้าจอ>"
  2. เลือกประเภทของข้อมูลพื้นฐานเป็น "<ชื่อประเภท>"
  3. คลิกปุ่ม "<ชื่อปุ่ม>"
  4. กรอกช่อง <ชื่อฟิลด์> "<ค่าที่กรอก>"
  5. กรอกช่อง <ชื่อฟิลด์> "<ค่าที่กรอก>"
  6. กรอกช่อง <ชื่อฟิลด์> "<ค่าที่กรอก>"
  7. กดปุ่ม "<ชื่อปุ่มบันทึก/ยืนยัน>"
- **Expected:** <ผลลัพธ์ที่คาดหวัง เช่น แสดงข้อความแจ้งเตือน "..." หรือ บันทึกข้อมูลสำเร็จและแสดงในตาราง>
- **Test Data:**
  1. "<ข้อมูลที่ใช้ในแต่ละขั้นตอน>"
  2. "<ข้อมูลที่ใช้ในแต่ละขั้นตอน>"
  3. "<ข้อมูลที่ใช้ในแต่ละขั้นตอน>"
```

> ⚠️ **ลำดับที่ต้องเรียงเสมอ:** `### TC` → `TC ID` → `TC Description` → `Test Step` → `Expected` → `Test Data`

## 4. โครงสร้าง Test Scenario (TS) หลัก

ทุกหน้าจอ/ฟีเจอร์ ให้จัดกลุ่ม Test Cases ภายใต้ **3 Test Scenario หลัก** ดังนี้:

| Test Scenario ID | ชื่อ Test Scenario | คำอธิบาย |
|---|---|---|
| **TS-STS-XX-01** | ตรวจสอบการกรอกข้อมูล | ทดสอบการกรอกฟิลด์ทุกช่อง ทั้ง Positive (ข้อมูลถูกต้อง) และ Negative (ข้อมูลผิดรูปแบบ, ว่าง, ซ้ำ, เกินความยาว) |
| **TS-STS-XX-02** | ตรวจสอบการทำงานของปุ่ม | ทดสอบปุ่มทุกปุ่มในหน้าจอ เช่น เพิ่มรายการ, บันทึก, ยกเลิก, แก้ไข, ลบ, ปิด/เปิดใช้งาน |
| **TS-STS-XX-03** | ตรวจสอบการแสดงผล | ทดสอบการแสดงผลหน้าจอ ตาราง, Dropdown, สถานะ, ข้อความแจ้งเตือน, Modal/Dialog |

> 📌 `XX` = รหัสหน้าจอ/ฟีเจอร์ เช่น `01` = ข้อมูลพื้นฐาน, `02` = รายชื่อนักเรียน  
> 📌 แต่ละหน้าจอสามารถ **เพิ่มหรือลด** Test Scenario ได้ตามความเหมาะสม แต่ให้อิง 3 กลุ่มหลักนี้เป็นฐาน

### รูปแบบโครงสร้างไฟล์ Test Cases

```text
# Test Cases: <ชื่อหน้าจอ>

## TS-STS-XX-01: ตรวจสอบการกรอกข้อมูล

### TC-STS-XX-01-01: <ชื่อ Test Case>
- **TC ID:** TC-STS-XX-01-01
- **TC Description:** ...
- **Test Step:** ...
- **Expected:** ...
- **Test Data:** ...

### TC-STS-XX-01-02: <ชื่อ Test Case>
...

---

## TS-STS-XX-02: ตรวจสอบการทำงานของปุ่ม

### TC-STS-XX-02-01: <ชื่อ Test Case>
...

---

## TS-STS-XX-03: ตรวจสอบการแสดงผล

### TC-STS-XX-03-01: <ชื่อ Test Case>
...
```

## 5. รายละเอียดแต่ละ Test Scenario

### TS-STS-XX-01: ตรวจสอบการกรอกข้อมูล
ครอบคลุม Test Cases ต่อไปนี้:
- **Positive:** กรอกข้อมูลถูกต้องครบถ้วน → บันทึกสำเร็จ
- **Negative - Format ผิด:** รหัสมีอักขระพิเศษ, เว้นวรรค, ภาษาไทย, ขึ้นต้นด้วยตัวเลข
- **Negative - Required:** ไม่กรอกฟิลด์ที่จำเป็น (ว่าง)
- **Negative - Duplicate:** กรอกรหัสซ้ำกับที่มีอยู่ในระบบ
- **Negative - Boundary:** กรอกเกินจำนวนตัวอักษรสูงสุด, ลำดับแสดงผลเป็นค่าติดลบ/ตัวอักษร

### TS-STS-XX-02: ตรวจสอบการทำงานของปุ่ม
ครอบคลุม Test Cases ต่อไปนี้:
- ปุ่ม "เพิ่มรายการ" → เปิด Modal ฟอร์ม
- ปุ่ม "บันทึก" → บันทึกข้อมูล
- ปุ่ม "ยกเลิก" → ปิด Modal โดยไม่บันทึก
- ปุ่ม "แก้ไข" → เปิด Modal แก้ไข
- ปุ่ม "ปิด" / "เปิด" → เปลี่ยนสถานะใช้งาน
- ปุ่ม "ลบ" → ลบรายการ (ถ้ามี)
- ปุ่ม "ยืนยัน" / "ยกเลิก" บน Dialog

### TS-STS-XX-03: ตรวจสอบการแสดงผล
ครอบคลุม Test Cases ต่อไปนี้:
- เข้าถึงหน้าจอสำเร็จ แสดงองค์ประกอบครบ
- Dropdown แสดงรายการครบถ้วน
- ตารางแสดงข้อมูลถูกต้องตามประเภทที่เลือก
- คอลัมน์ตารางแสดงครบ (ลำดับ, รหัส, ชื่อ, สถานะ ฯลฯ)
- สถานะแสดงผลถูกต้อง (เปิดใช้งาน/ปิดใช้งาน)
- ข้อความแจ้งเตือน/Error แสดงถูกต้อง

## 6. การบันทึกผลลัพธ์

- บันทึก Test Cases ทั้งหมดลงในไฟล์ Markdown ในโฟลเดอร์ `testcases/` (เช่น `testcases/master-data.md`)
- จัดกลุ่มตาม Test Scenario (TS) เสมอ
- หรือนำเสนอในรูปแบบ Markdown List / ตาราง ให้ผู้ใช้นำไปใช้งานต่อใน Excel / Test Management Tool ได้ทันที
